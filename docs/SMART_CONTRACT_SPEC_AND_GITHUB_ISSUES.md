## 🏛️ System Architecture Overview: The "Gasless Intent-to-Escrow" Flow

```
   [ Buyer ] (Sends USDC to generated Intent deposit address)
       │
       ▼
   [ NEAR 1-Click Intent API / Solvers ] (Fulfills cross-chain swap)
       │
       ▼ (Webhook / Relayer triggers on COMPLETED)
   [ AgriFlow Gas Master (ERC-2771 / Relayer) ] ── (Sponsors Gas Fees)
       │
       ▼
   [ AgriFlowEscrow.sol ] ──────────────────────── (Funds & Trade Hash locked in Vault)
       │  • Stores generated deposit wallet address
       │  • Stores immutable cryptographic trade details hash (keccak256)
       │
       │ (Logistics delivers goods & uploads Proof of Delivery)
       ▼
   [ Buyer confirms delivery ] ─────────────────── (Gasless meta-tx via Gas Master)
       │
       ├───► Withdrawable Balance: Supplier (Goods Amount)
       ├───► Withdrawable Balance: Logistics (Haulage Fee)
       └───► Treasury (1% Platform Fee)
       │
       ▼
   [ Supplier / Logistics Dashboard ] ──────────── (Calls withdraw() with zero gas friction)
```

### Key Architectural Invariants:
1. **Generated Wallet Address & Audit Record**:
   - The contract explicitly stores `depositAddress` (the unique deposit address generated by the Intent API) associated with the `tradeId`.
2. **Cryptographic Trade Details Hashing**:
   - Stores an immutable `detailsHash = keccak256(abi.encodePacked(tradeId, buyer, supplier, logistics, goodsAmount, logisticsAmount, depositAddress, intentTxHash))` so all off-chain order parameters are cryptographically anchored and verifiable against tampered data.
3. **No-Crypto Friction (Gas Master / ERC-2771)**:
   - Users (buyers confirming receipt, suppliers withdrawing) do **not** need native gas tokens (ETH/MATIC) in their wallets—the AgriFlow Gas Master pays network gas on their behalf.
4. **Pull-over-Push Vault Pattern**:
   - Upon buyer confirmation, funds are credited to internal mapping balances (`withdrawableBalances`), allowing suppliers and haulers to pull funds on demand.

### 📌 ISSUE 1 (Assigned to: Chibuike) — Created (#49)
**Title:** `[CONTRACT-DEV] Implement AgriFlowEscrow.sol with Multi-Party Escrow, Generated Address Tracking & Trade Hashing`  
**Assignee:** `chibuike`  
**Labels:** `smart-contracts`, `solidity`, `escrow`, `chibuike`, `P0`

#### Description:
Build the core `AgriFlowEscrow.sol` contract adhering to OpenZeppelin v5 standards with reentrancy protection, safe ERC-20 handling, generated address tracking, and cryptographic trade detail hashing.

#### Requirements:
- [ ] **State Machine**: Implement statuses (`NONE`, `FUNDED`, `COMPLETED`, `DISPUTED`, `REFUNDED`).
- [ ] **Data Model**: Struct `Trade` capturing:
  ```solidity
  struct Trade {
      bytes32 tradeId;
      address buyer;
      address supplier;
      address logistics;
      address token;              // address(0) for native ETH, or ERC20 USDC
      address generatedDepositAddress; // Generated wallet address from Intent API
      bytes32 detailsHash;        // keccak256 cryptographic hash of transaction details
      string intentTxHash;        // Proof of deposit transaction hash
      uint256 goodsAmount;        // Payable to Supplier
      uint256 logisticsAmount;    // Payable to Logistics Carrier
      uint256 platformFee;        // 1% platform fee
      TradeStatus status;
      uint256 createdAt;
      uint256 fundedAt;
  }
  ```
- [ ] **Hashing & Validation Function (`computeTradeHash`)**:
  - Pure/view function calculating `keccak256(abi.encodePacked(tradeId, buyer, supplier, logistics, goodsAmount, logisticsAmount, generatedDepositAddress))`.
- [ ] **Relayer / Intent Funding (`fundTradeFromIntent`)**:
  - Callable by authorized `relayer` or `owner` when NEAR 1-Click Intent completes.
  - Records `generatedDepositAddress`, computes and stores `detailsHash`, and locks USDC in escrow.
- [ ] **Buyer Confirmation (`confirmDelivery`)**:
  - Callable by `buyer` (or via Gas Master forwarder).
  - Validates `status == FUNDED`.
  - Credits `withdrawableBalances[supplier]`, `withdrawableBalances[logistics]`, and `withdrawableBalances[treasury]`.
- [ ] **Withdrawal Functions (`withdraw` & `withdrawETH`)**:
  - Implements Checks-Effects-Interactions (CEI) to prevent reentrancy.
  - Allows suppliers, haulers, and treasury to withdraw credited balances anytime.
- [ ] **Dispute Resolution (`raiseDispute`, `refundBuyer`)**:
  - Admin/Arbitrator override to refund buyers if goods fail inspection.
- [ ] **ERC-2771 Context Support**: Inherit `ERC2771Context` so `_msgSender()` resolves the end-user rather than the Gas Master forwarder.

### 📌 ISSUE 3 (Assigned to: Kennedy)
**Title:** `[TESTING] Comprehensive Test Suite, Trade Hash Invariants & Fuzzing for AgriFlowEscrow.sol`  
**Assignee:** `kennedy`  
**Labels:** `testing`, `hardhat`, `foundry`, `qa`, `kennedy`, `P0`

#### Description:
Build complete test coverage using Hardhat/Foundry for all escrow states, generated deposit address tracking, cryptographic hash validation, and invariant rules.

#### Requirements:
- [ ] **Happy Path Test**:
  1. Relayer funds trade on behalf of buyer with generated wallet address and intent tx hash.
  2. Verify trade `detailsHash` matches cryptographic signature of parameters.
  3. Buyer calls `confirmDelivery()`.
  4. Verify status becomes `COMPLETED` and balances are credited.
  5. Supplier, Logistics, and Treasury call `withdraw()` and receive exact token amounts.
- [ ] **Security & Negative Tests**:
  - Non-buyer tries calling `confirmDelivery()` $\to$ Must revert.
  - Tampered hash or duplicate trade funding $\to$ Must revert.
  - Supplier attempts calling `withdraw()` before delivery is confirmed $\to$ Must revert with `"No balance"`.
  - Attacker attempts double-withdrawal (Reentrancy attack simulation) $\to$ Must revert.
  - Non-relayer attempts calling `fundTradeFromIntent()` $\to$ Must revert with `"Unauthorized"`.
- [ ] **Dispute & Refund Scenarios**:
  - Buyer raises dispute $\to$ status moves to `DISPUTED`.
  - Admin executes `refundBuyer()` $\to$ Buyer receives 100% refund; supplier balance remains 0.
- [ ] **Invariant Fuzzing**:
  - `Total Locked Escrow + Total Withdrawable Balances == Contract Token Balance` at all times.
